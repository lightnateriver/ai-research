调研概述

调研背景：当前 LLM API 服务的会话级 KV Cache 多为多租户共享存储，高并发时用户的缓存可能被其他用户的会话挤掉，导致缓存命中率下降。用户构想的商业模式是：在购买 API / Token Plan 时，能否额外购买一块专属存储来存放自己的 KV Cache，从而避免被其他用户挤掉。

调研目标：系统调研 8 家主流云厂商（OpenAI、Anthropic、火山引擎、阿里云、腾讯云、华为云、AWS、Google Cloud）是否存在"专属 KV Cache 存储"的商业模式或接近的产品方案。

核心结论

结论摘要

用户构想的"在 Token Plan 里额外购买一块物理隔离的专属 KV Cache 存储"，目前所有主流云厂商都没有提供。

行业现状分为两个层面：API 层（共享基础设施上的逻辑缓存，个人可用，按 token 或时长计费）和 自建推理层（独立的分布式 KV 存储产品，需自建推理引擎，门槛高，多为企业级）。

最接近用户构想的产品是 Google Vertex AI 显式缓存（API 层 + 按小时收存储费 + 个人可用）和 腾讯云 HAI 共享 KVCache（半托管 + 一键开启 + 个人低门槛）。

各厂商产品详细说明

Google Cloud — Vertex AI Context Caching 最接近"买存储"

六家中唯一在 API 层面明确按"存储时长"收费的产品，个人开发者可直接使用。
两种模式：① 隐式缓存（所有 project 默认开启，自动，无存储费，90%折扣）；② 显式缓存（通过 caches.create API 创建 CachedContent 对象）
存储费：显式缓存 $4.5 / 百万 token / 小时
TTL：默认 60 分钟，可更新，无最大时长限制
最低缓存：Gemini 3.x 为 4096 token；Gemini 2.x 为 2048 token
命中折扣：Gemini 2.5+ 为 90%；Gemini 2.0 为 75%
隔离性：按 Google Cloud project 逻辑隔离，共享底层基础设施
评价：最接近用户构想的"买存储"概念——你手动创建缓存对象，按存储时长付费，个人账号即可用。但仍是共享基础设施上的逻辑缓存，非物理隔离专属存储。

腾讯云 — HAI 共享 KVCache + FlexKV 个人门槛最低

HAI 是一键部署 GPU 模型服务的平台，KVCache 是其可信集群的一个功能开关。
HAI 共享 KVCache：创建 HAI 可信集群时可开启"全局共享 KVCache 缓存池"，将缓存从显存下沉至分布式缓存/存储
FlexKV：腾讯自研 KV Cache 卸载技术，已合入 vLLM / NVIDIA Dynamo / TensorRT-LLM 官方主线
起步成本：GPU 基础型 1.2 元/小时起；有 1 元 = 8 小时体验券
计费：含在 HAI 实例费用中，KVCache 无单独费用
开放状态：KVCache 能力逐步开放中，具体以控制台为准
隔离性："全局共享 KVCache 缓存池"为平台级共享，非独占
评价：个人开发者拥有 KV 缓存存储能力的最低门槛方案——不需要自己搭建推理引擎，HAI 一键部署后打开开关即可，1 元体验券即可上手。但缓存池是共享的。

AWS — Bedrock Prompt Caching 标准 API 层

Amazon Bedrock 的标准 prompt caching 功能，支持多家模型提供商。
机制：显式 cache checkpoint，支持 Converse / InvokeModel API
TTL：5 分钟（默认）/ 1 小时（部分 Claude 模型，需指定 ttl=1h）/ 30 分钟（GPT-5.6 系列）
计费：无单独存储费；cache write 按 1.25x 输入价（GPT-5.6），cache read 90% 折扣
特殊：cached tokens 不计入速率限制
最低缓存：1024-4096 token 视模型而定
另：SageMaker HyperPod 有 Managed Tiered KV Cache（自建推理层面，企业级）
评价：标准的 API 层缓存方案，个人可用，但没有"买存储"的概念——缓存是自动管理的易失性缓存，TTL 到期即清除。

阿里云 — 百炼显式缓存 + KVCacheStore + PAI FlashKV 产品最全

阿里云是产品矩阵最全的一家，同时覆盖 API 层和自建推理层。
① 百炼显式缓存（API层）：通过 cache_control 标记，100% 确定性命中，不受后端资源调度影响，5 分钟 TTL 命中自动续期
百炼计费：cache write 125% / hit 10%；无存储费；个人可用
② KVCacheStore（独立产品）：百 PiB 级分布式 KV 存储，按配置容量计费
KVCacheStore 门槛：起步 300 TiB，300 TiB 步长扩容；需挂载智能计算灵骏裸金属节点
③ PAI FlashKV：分布式 KV-Cache 服务，集群级跨实例共享，面向自建推理
④ Tair KVCache：显存-内存-SSD 三级缓存系统，面向自建推理
评价：百炼显式缓存的"100% 确定性命中"直接解决了用户担心的"被挤掉"问题（通过 API 层面的保证，而非物理隔离）。但真正的独立 KV 存储产品 KVCacheStore 是 300TiB 起步的企业级产品，个人基本不可用。

火山引擎 — EIC 弹性极速缓存 + 方舟上下文缓存 EIC 公测免费

火山引擎同时提供 API 层的方舟上下文缓存和自建推理层的 EIC 分布式 KV 存储。
① 方舟上下文缓存（API层）：前缀缓存 + Session 缓存，通过 previous_response_id 引用，最长 72 小时
方舟计费：按 token×小时 收存储费（如 DeepSeek-R1: 0.017元/百万token/小时）；命中输入享折扣
② EIC 弹性极速缓存（自建层）：分布式 KVCache 存储服务，GDR 零拷贝（时延降至 1/50），Namespace 级隔离与治理
EIC 兼容性：兼容 vLLM / SGLang / LMCache，提供 C++/Python SDK
EIC 使用方式：创建 VKE GPU 集群 → 创建 EIC 实例 → 在推理引擎配置中填入 EIC instanceID 和 endpoint
EIC 计费：公测期间暂不收费，后续规则待定；部分模板需申请邀测
评价：EIC 是真正的"买一块 KV 缓存存储"产品形态，且公测免费。但需要你自己在 VKE 上部署推理引擎，个人开发者如果有 GPU 集群可以尝试。方舟 API 层的上下文缓存则个人可直接用。

华为云 — EMS 弹性内存存储 + Mooncake 公测审核制

EMS 明确做 KV Cache 缓存，但目前处于公测阶段，审核制偏向企业客户。
EMS 定位：通过缓存历史 KV Cache，以存代算，提升推理吞吐、节省算力、降低时延
部署模式：半托管融合部署，数据面部署在用户 AI 节点本地，纳管空闲内存资源
搭配使用：AI 开发平台 ModelArts / CCE 容器集群
开通方式：公测阶段，需申请公测并通过审核，需填写企业规模、研发人员比例、应用场景等
计费：按需付费（后付费），每小时结算，具体费率需提工单咨询
Mooncake：开源 KVCache 复用系统，可安装在 ModelArts 专属资源池
评价：EMS 产品定位清晰，但公测审核制明显偏向企业客户，个人开发者申请通过的可能性较低。需要搭配 ModelArts 或 CCE 使用，属于半托管自建推理方案。

OpenAI — Prompt Caching（自动） 标准 API 层

OpenAI 的 prompt caching 是自动的，无需手动标记，没有"买存储"选项。
机制：自动前缀缓存，≥1024 token 自动缓存，按 128 token 递增
TTL：GPT-5.6+ 支持 prompt_cache_options.ttl=30m（默认，唯一值）；旧模型 5-10 分钟不活动后清除，1 小时内一定移除
计费：cached read 为输入价的 10%（GPT-5 系列）/ 50%（GPT-4o/o-series）；旧模型无 write 溢价
隔离性：按 API Key / 组织逻辑隔离
专属存储：无。没有任何"额外购买专属 KV 缓存存储"的选项
另：File Search 有 vector store 存储（$0.10/GB/天），但那是 RAG 向量检索，非 KV cache
评价：OpenAI 在 KV 缓存商业化上最为保守——纯自动缓存，无显式控制，无存储费，无专属存储选项。缓存完全由平台管理，高并发时可能被驱逐。

Anthropic — Prompt Caching 显式控制 API 层

Anthropic 是最早将 prompt caching 做成 API 一等公民的厂商，支持显式 cache_control 标记。
机制：显式 cache_control 标记，最多 4 个断点，精确控制缓存边界
TTL：5 分钟（默认 ephemeral）/ 1 小时（付费，2x write price）
计费：cache write 1.25x（5m）/ 2x（1h）；cache hit 0.1x；无单独存储费
隔离性：按 Workspace 隔离（Claude API/AWS/Microsoft Foundry），按 Organization 隔离（Bedrock/Google Cloud）；缓存不跨组织共享
专属存储：无。虽然有逻辑隔离，但缓存仍是易失性的，存在共享基础设施上
最低缓存：1024 token 起
评价：Anthropic 的缓存控制粒度最细（4 个断点 + 两档 TTL），按 Workspace 隔离也相对严格。但仍然没有"买一块专属持久化存储"的选项，缓存 TTL 最长仅 1 小时。
个人开发者推荐路径

如果你是个人开发者，想立刻体验"拥有自己的 KV 缓存存储"

路径一（最轻量）：API 层显式缓存
使用 Google Vertex AI 显式缓存 或 阿里云百炼显式缓存——纯 API 调用，按存储量/时长付费，不需要管基础设施。Google 的按小时存储费最接近"买存储"概念；阿里云的 100% 命中保证最直接解决"被挤掉"问题。
路径二（想拥有实际存储层）：半托管一键部署
使用 腾讯云 HAI——一键部署 GPU 实例，打开 KVCache 开关即可，1 元体验券即可上手。不需要自己搭建推理引擎，但拥有自己的 GPU 实例和缓存池。或尝试 火山 EIC（公测免费，需 VKE GPU 集群）。
路径三（企业级/大规模）：自建推理 + 独立 KV 存储
使用 阿里云 KVCacheStore（300TiB 起步）、华为云 EMS（公测审核制）、AWS SageMaker HyperPod 等——真正的物理隔离专属 KV 存储，但门槛和成本都很高，适合企业级大规模推理部署。
行业趋势与未来方向

观察与判断

1. 两层分化明显：API 层（共享缓存，个人可用，按 token 计费）和自建推理层（独立 KV 存储产品，企业级，按容量计费）之间存在明显的断层。用户构想的"API 层 + 专属存储"恰好处于这个断层中。

2. "以存代算"成为共识：六家厂商都推出了 KV Cache 卸载/分层存储产品（EIC、KVCacheStore、EMS、FlexKV、SageMaker HyperPod、Tair KVCache），说明将 KV 从 GPU 显存卸载到独立存储是行业明确趋势。

3. API 层开始收存储费：Google Vertex AI 显式缓存按小时收存储费、火山方舟按 token×小时收存储费，说明"为缓存存储付费"的商业模式正在 API 层萌芽。

4. 学术前沿：arXiv 论文 "Can I Buy Your KV Cache?"（2026.06）提出了 "prefill CDN" 概念——发布者预计算 KV、其他 agent 付费加载，论证了经济学可行性，但尚未商业化。

5. 机会判断："在 Token Plan 中附加购买专属 KV 缓存存储"目前是空白市场。随着长上下文和 Agent 工作负载增长，缓存命中率的稳定性将成为刚需，这个方向可能成为下一个商业化机会。
